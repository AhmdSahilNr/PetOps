## Safe execution

The seven repository-tooling checks use `unittest` and do not invoke application database fixtures:

```powershell
.venv/Scripts/python.exe -m unittest scripts.test_repository_hardening -v
```

The JavaScript harnesses can also run directly, without the Python application's autouse fixtures:

```powershell
node tests/ui_races.mjs
node tests/ui_product.mjs
```

Do not run application pytest commands against retained demo or human-testing data. `tests/conftest.py` migrates and clears the selected database. Its guard allows loopback PostgreSQL names ending in `_test`; that alone does not make an existing database disposable.

For a later authorized application check, create a separate empty `petops_regression_test` database, set `PETOPS_TEST_DATABASE_URL` privately to it, verify the resolved target, and then run the required selection. Install Node (20 or later, as required by the harness integration) or set `PETOPS_NODE` privately. See [developer setup](../developer/SETUP.md). SQLite fallback is not evidence of PostgreSQL constraint/concurrency behavior.
